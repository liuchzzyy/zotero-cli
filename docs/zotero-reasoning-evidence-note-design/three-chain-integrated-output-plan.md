# ai-note2 三链一体输出优化框架与实施计划

状态：**方案待确认，尚未实施**。本文基于 `feat/ai-note2` 的 `7c8402a`、审查时的未提交工作区改动，以及条目 `FK5UDDB2` 的本地运行 `0001` 制定。该运行未保存完整代码和提示词 hash，不能证明它由当前工作区的确切版本生成。本方案中的真实条目示例是对已有产物和冻结文本的人工核查示意，并非新一次模型生成结果。

## 1. 目标与范围

交付一篇以论文论证为主线、可以独立阅读的框架分析笔记。读者在同一论点附近，应能找到：

1. 作者提出了什么命题，以及命题的条件和来源。
2. 作者报告了什么实验、计算或文献材料；对象、方法、数值、单位、测试条件和出处是什么。
3. 作者如何从这些材料推向命题；是否是作者明示或基于文本的重构。
4. 哪些特定结果、关联或推理步骤受到何种审查；依据、判准、判断、影响与未解问题是什么。
5. 有无针对该命题、且覆盖相应范围的综合评议。没有时明确显示“未有针对该命题的综合评议”，不由局部审查推导一个新结论。

“思维链”仅指对论文**公开论证**的整理，不要求或声称展示模型内部思维过程。三链在权威数据中保持语义分工，在阅读视图中按明确关系融合。

本轮聚焦纯文本输入与 `ai-note2` 现有功能：保留 MinerU 冻结文本、表格文字、公式文字、图注和脚注；不引入图片像素分析、外部文献抓取、跨运行对象对齐或自动科学评分。输出采用蓝色主色调，生成的 `tree.svg` 在发布时作为附件上传到 Zotero；旧 AI note 仍只能作为辅助线索，不代替原文定位。

**写作规范：**生成文本应遵循 ASD-STE100（Simplified Technical English）的清晰写作原则：同一概念使用一致术语，短句表达一个主要事实，明确动作主体、对象、条件与判断；保留科学符号、限定语和不确定性。ASD-STE100 是面向英文的受控语言标准，本功能当前输出简体中文，按其原则适配中文表达，不宣称中文文本通过 ASD-STE100 正式合规认证。论文原文、公式、引文、专有名词和不可翻译的技术术语不因写作风格而改写。

## 2. 已知基线与问题

- `analysis.json` 是唯一完整科学内容源；`object-index.json`、Markdown、HTML 与 SVG 是可重建视图。现有实现已有 `TC-N`、`TC-L`、`EC-E`、`EC-M`、`RC-Q`、`RC-S`、`RC-A` 等对象，记录来源、关系和状态。
- `FK5UDDB2/0001` 包含 78 个对象、48 条索引关系；来源复核记录为 63 个“支持”、14 个“部分支持”、1 个“无法核对”。这是模型对对象与来源的判断统计，不是论文正确率，也不是独立人工审查结果。
- 当前 `note.md` / `note.html` 先罗列关系，再分别列三链对象。多个详细字段以嵌套 JSON 展开，阅读时需要跨文件和 ID 手动拼接。`tree.svg` 中同一分支的理由存在坐标重叠，且当前图未展示具体证据对象。
- `FK5UDDB2` 的 `EC-E010` 把作者提出的 knock-off 解释登记为结果，并由 `EC-M006` 作为机制命题的论证依据。原文保留了“可能解释”和进一步实验确认的语气；这条关系有解释作为自身依据的风险。`RC-Q004` 提出验证边界，但没有指出这一关联的循环性。
- `TC-N006` 的 1H NMR 细节被来源核对判为部分支持：所引块未明确该方法。现有来源不足以核实该细节，也不足以认定它必然错误。
- 当前工作区 `generation.py::_normalize_candidate()` 会自动改写 `reliability_statement.scope`、`review_scope`，并可能替“已定位”的状态填入第一条记录来源。此行为涉及语义与定位，不能仅按格式规范化理解。这里记录的是当前工作区行为，不断言它已影响 `FK5UDDB2/0001`。

## 3. 总体架构

```text
冻结输入：主文 / SI 的文本块、表格文字、公式、图注、旧 AI note
  ↓
生成：作者论证 TC + 报告材料 EC + 定点审查 RC
  ↓
结构、引用、来源区间与图号校验；分配运行内 ID
  ↓
来源复核：程序核对定位 + 模型判断对象和关联的文字依据
  ↓
analysis.json（权威科学内容）+ run.json（运行与复核记录）
  ↓
object-index.json（可重建关系索引）
  ↓
论点阅读投影（由程序确定性组装，引用既有对象）
  ├─ note.md / note.html：面向阅读的三链一体正文，蓝色主题
  ├─ overview.md、thought.md、evidence.md、review.md：追溯与完整字段
  └─ tree.svg：本地辅助图；发布时作为父条目的独立 Zotero 附件上传
       ↓
     回读确认 note、SVG 附件和父条目标签，全部完成才标记发布完成
```

**单一真源：**保留 `analysis.json` 为唯一科学内容源。阅读投影由同一已校验文档、索引和复核报告确定性派生，不新增模型生成的独立科学总结、不建立第二份可编辑的权威内容。`run.json` 保留本次来源复核与执行事实。可以在内存构造投影；第一阶段不新增单独的持久投影文件，避免产生新状态和同步负担。

**证据优先级：**科学结论以冻结论文原文为依据；旧笔记仅提供候选线索。程序验证对象与引用的结构，模型给出可复核的来源判断，科学准确性仍须人工结合原文和图像检查。

## 4. 阅读单元与导航

### 4.1 文档层次

1. **研究范围与阅读边界**：父条目、附件身份及是否待核、来源范围、无图像像素、运行标识、来源复核状态。
2. **核心论点与综合判断**：列出已有核心论点；只有存在指向该命题的 `RC-A` 时才显示它自己的结论、范围和理由。若无评议，写明未有综合评议。多核心论点分别展示，不合并为新命题。
3. **按分论点组织的分析正文**：每个阅读单元按下文 4.2 顺序展示；理由节点不超过既有论证树的三级。不能建立正式关联的材料留在候选或独立材料区。
4. **未关联材料、候选与未覆盖范围**：列出未正式关联的证据、待决候选、未评议命题、未检查或当前不可检查的覆盖单位。没有记录不等于相关检查已完成。
5. **来源与技术索引**：列出必要的对象 ID、附件、PDF 页和块号；更完整的结构字段留在本地详细视图及 `analysis.json`。

### 4.2 单个论点阅读单元

| 展示项 | 数据来源 | 阅读规则 |
| --- | --- | --- |
| 论点 | `TC-N` | 展示原有命题、限定、归属与来源，不擅自强化语气 |
| 报告材料 | 已有 `EC-M` 指向该节点、支持关系或 bridge 的 `EC-E` / `EC-U` | 明确报告类型、对象、方法、条件、结果与来源；有联合组时保留各成员身份和作用 |
| 作者推理 | `TC-L.bridge`、用途说明、归属与关联出处 | 标明作者明示或文本重构；结果对节点、整条边和 `bridge` 的直接关联分开 |
| 定点审查 | 目标直接指向当前 `TC-N`、`TC-L`、`bridge`、关联的 `EC-M` 或该单元直接呈现的证据对象的 `RC-Q` | 同时展示问题、判准、依据、结论、范围、影响与开放状态；证据自身的审查要标明其实际目标 |
| 该命题综合评议 | `RC-A.target_ref` 精确指向当前命题 | 展示已有结论、正反材料、范围和未评部分；缺失时显式标记 |
| 来源复核 | 对应对象的独立复核条目 | 显示支持 / 部分支持 / 不支持 / 无法核对及原因；无记录时显示未提供 |

节点、边与 `bridge` 使用原有身份，`bridge` 仍是边属性。结果经多级路径到达上层命题时，使用“沿某条已登记路径汇集”表述，并列出路径；不得显示为直接证据。更稳妥的首版只就地展示**直接挂载**的材料及其实际目标，路径汇集留待明确可读性需求后实现。

### 4.3 同一对象多次使用

- 相同证据可在多个阅读单元按同一 ID 引用；首次出现展开必要内容，后续显示简短引用与实际用途。对象仍只在 `analysis.json` 定义一次。
- `EC-G` 表示共同来源，`EC-U` 表示作者联合使用：二者不等于独立重复验证，也不按对象数或路径数计算支持强度。
- 一个审查可能触及多个对象，展示时保留其原始主要目标、相关目标和范围；不得因出现在某个单元中而改称该审查直接评议整个分论点。
- 图号只表示文本/图注有该图号；不得暗示已查看图像、曲线、显微照片或原始数据。HTML 仅依赖标题、段落和列表；ID 可见，不能要求脚本或锚点才能理解。

### 4.4 蓝色主题与跨渲染器显示

阅读视图采用统一的蓝色主色调，主题作用于 `note.md`、`note.html` 和 `tree.svg` 的可见部分；分链 Markdown 明细采用同一标题、强调和状态标识规则。建议的初始颜色用于实现和验收，不表示已在 Zotero 验证：

| 用途 | 建议颜色 | 应用 |
| --- | --- | --- |
| 主标题、核心论点 | 深蓝 `#17365D` | 标题、核心对象与重点标签 |
| 分论点、链接和结构线 | 蓝色 `#245A8D` | 二级标题、关系线和引用 |
| 证据与作者推理 | 中蓝 `#376C9D` | 标签、细边框和提示 |
| 背景及信息区 | 浅蓝 `#EAF2FA` | 支持背景色的渲染器中的信息区 |
| 正文及未着色回退 | 深灰 `#202B36` | 保持正文易读 |

Markdown 标准没有统一的文字颜色语法，不能承诺所有 Markdown 查看器显示颜色。`note.md` 保持标准 Markdown 的标题、粗体、列表和状态文字；在目标查看器允许安全内联 HTML 的位置使用经转义、最小化的颜色标记，不依赖外部 CSS、JavaScript、网络字体或截图。查看器过滤 HTML 时仍可完整阅读。以色块为主的 HTML 视觉布局不作为 Markdown 必需条件。

Zotero 使用的 `note.html` 由程序渲染，优先验证 Zotero 实际保留的内联样式；必须测试 Zotero 存储与回读后颜色是否仍显示。若 Zotero 过滤样式，保持正文和状态标签完整，并如实报告颜色渲染限制，不声称上传成功即代表显示成功。SVG 使用同一蓝色家族，但审查状态同时以文字、形状或线型区分，不只依靠颜色；对比度、浅色和深色显示环境以及打印可读性均需检查。颜色不表达科学可靠性等级。

主题色和可调整的显示策略遵循项目配置约定：统一在 `src/zotero_cli/config/defaults.toml` 定义并由运行配置读取，示例配置与生效配置视图同步；不要在渲染模块散落另一套可调默认值。先盘点现有 `[ai_notes2.appearance]` 与消费者，再决定新增哪些必要配置，避免无用选项。

### 4.5 ASD-STE100 写作执行

- 生成三链对象的自然语言字段、来源复核说明和最终可见分析文本均以 ASD-STE100 的清晰写作原则为写作要求：一个概念使用一个术语；短句明确主体、动作、对象和条件；避免多重否定、含糊代词、长串名词和无依据的因果词。
- 明确区分“作者报告”“作者推断”“模型来源复核”“审查判断”；缺少材料时写“当前输入未找到”或“无法判断”，不把它改写为“原文没有”或“已证明”。结果的样品、单位、对照、范围和不确定性不得为了句子简短而省略。
- 中文输出是对英文规范原则的适配；英语输出如未来纳入范围，是否具备受控词典、完整规则及正式合规验证另行确认。科研专有名词和原文引用保持准确，不因词汇控制替换材料名或改变原意。
- 提示词和渲染文案同步这一要求；通过真实产物人工审阅术语一致性、句子可读性及科学限定保留。不要根据句长、指定词表或固定措辞建立硬阻断，避免误伤科学内容。

## 5. 科学语义与复核设计

### 5.1 区分结果、解释和审查

| 类别 | 应如何表述 | 不能推导出的结论 |
| --- | --- | --- |
| 实验测量或处理结果 | 保留样品、方法、条件、原始结果和不确定度 | 结果自动证明唯一机制 |
| 模型拟合、模拟或理论计算结果 | 保留模型、参数、适用体系及计算条件 | 与实验独立验证充分、或能直接代表实际器件 |
| 作者假说或机制解释 | 放入作者命题、推理桥或明确标记的解释字段；保留“可能”等限定 | 解释本身是一项新的独立观测，或能证明其自身 |
| 文献材料 | 标记当前论文转述或实际取得原始文献的阅读范围 | 已核查未取得的原始文献全文 |
| 审查者推断 | 用 `RC-Q` 记录目标、判准、依据、范围及结论 | 可以替作者改写论点，或把缺失信息直接定为论文错误 |

修改生成提示词：明确禁止将同一解释换名登记为独立结果后回指自身；处理或派生关系必须有可定位的作者依据，无法确认时保留候选、未关联材料或不建立关系。不要要求论文必须给出某类结果，也不要强行将每条证据挂到论点。

将循环支持、过度归类、关系方向与限定丢失列为**语义复核问题**：由模型指出具体对象、关系、来源和解释，并供人工检查；不可用固定关键词、数值或文本相似度作为致命判定。某项复核结果需要人工注意时，保留原对象与复核结论，不静默修正文献事实。

### 5.2 保留两种不同的检查

1. **确定性结构与来源核对**：验证 JSON、字段、枚举、身份、引用闭合、图结构、来源三元组、span/原文片段与图号。它证明程序接收的引用和冻结输入一致，不证明摘录支持科学内容。
2. **模型来源与关系复核**：在现有第二步内检查对象陈述与其声明来源是否相符，同时明确核对关联的主体、目标、方向、作者用途和语气。对 `EC-M` / `EC-P` 等关系，把两端对象的必要字段、关联自身及对应来源一起提供；不可仅把关联描述送审后宣称检查了两端关系。优先复用现有 `verdicts` 对象状态与说明；若需要字段级或关系级新增状态，直接调整当前契约并同步调用方和测试，按第 8 节处理既有数据影响。

模型未能确认的来源、关系或审查应在阅读单元旁显示；模型可在说明中指出**其他冻结块可能相关**，但不得伪造正式来源或静默改写权威记录。现有 `_parse_verdicts` 仅接受对象已登记来源，若要支持“建议补充来源”，须单独设计为非权威建议，不能混入已核准引用。本轮优先保留其限制并清楚展示“现有引用不足”。

复核与生成可使用同一配置模型链；第二次模型调用**不是**独立专家审查，也不能通过计数给出准确率。记录实际返回模型、可得用量、完成原因和调用阶段；缺失记未知。若当前客户端只保存最后一次调用的元数据，应分别采集生成、每次结构修复和复核的实际记录；不把某一次 `usage` 描述为全流程总用量。

### 5.3 安全处理模型输出规范化

- 格式层面的确定性修正仅处理不改变科学含义且可验证的编码形式；保留必要的原始模型响应或变更记录，用于诊断。临时调试文件放受保护的状态或 scratch，避免提交私人文献内容。
- 不静默把一段审查范围覆盖为另一段范围，也不把任意首个来源块自动声明为某字段的“已定位”依据；已有差异应保留为可见不一致或请求模型按原文修复。
- 审查范围的自然语言措辞不同不应仅因字面差异中止任务；结构身份、覆盖对象与状态使用明确引用匹配。科学语义无法自动判断时保留双方文本及待核状态，不假装等价。
- 缺失字段的状态必须表达**实际可确定的事实**。不能仅因字段为空就推定原文没有、也不能把未确认的文献来源一律写成“不适用”。允许不确定或待核，禁止自动补科学数值和条件。

### 5.4 记录与版本

新的生成运行应记录代码版本、提示词及关键配置摘要、输入摘要、输出 schema / 索引 / 视图版本、请求阶段及实际返回模型。工作区有未提交改动时，仅记录 commit hash 不足以定位实际代码；需记录相关文件内容 hash 或明确 dirty 状态，并以实际可取得的信息为准。不得保存密钥。

显示变更单独提高 `view_version`；权威 JSON 的字段或语义若需调整，直接更新当前实现及其调用方和测试，并记录实际版本影响。旧数据不自动转换；如果调整将使用户现有数据无法读取、需要迁移或可能丢失，应先说明具体影响并取得决定。老运行不补造代码 hash，不静默回写旧目录或 Zotero。

## 6. 基于 FK5UDDB2 的阅读示例

以下是使用现有对象人工排版的**目标展示样例**。所有数值与描述只表示冻结文本中可定位的论文报告；该示例不是新模型结果，也不把模型复核当成人工定论。

### 6.1 室温 H- 电导及适用范围

**作者论点 `TC-N002`：**名义 x = 0.1 的样品在 23 °C 的离子电导为 1.8 mS cm-1，离子迁移数为 99.98%。`TC-N001` 将其用于室温快速 H- 传导这一核心论点。

**报告材料 `EC-E003`：**作者根据复阻抗等效电路的 R1 计算离子电导，使用离子与电子电导估计迁移数。正文 PDF p.2，块 `set-1 / B0025`；这两个值属于同一测量与分析体系，不应计作两项独立验证。模型对该对象的来源判断为“支持”，这一判断不证明原始阻抗拟合可靠。

**作者用途与推理：**`EC-M001` 将该结果用于 `TC-N002`；`TC-L012` 记录高离子电导与高迁移数用于支持室温快速 H- 传导。路径是 `EC-E003 → EC-M001 → TC-N002 → TC-L012 → TC-N001`，不能把 `EC-E003` 称为直接指向 `TC-N001` 的已登记用途。

**定点审查 `RC-Q002`：**该问题直接审查 `EC-E003` 的测量条件。SI PDF p.6，块 `set-2 / B0025` 说明测量在 H2 气氛升温时进行；因此把结果外推至空气、不同湿度或器件环境需要额外证据。这一限定不直接否定 H2 气氛下的报告值。该对象的模型来源判断为“支持”。

**评议边界：**现有 `RC-A001` 针对核心论点给出“有支持但须限定范围”，并引用气氛等审查；`TC-N002` 本身没有单独的综合评议。以上两者不能混为一谈。

### 6.2 knock-off 机制与未决关系

**作者论证：**`TC-N006` 和 `TC-N017` 整理作者对 H- 扩散与 knock-off 机制的讨论。冻结正文 `set-1 / B0037` 将协同迁移作为可能解释，并指出仍需进一步实验，例如中子散射。

**已有材料与限定：**`EC-E007` 报告 NNP-MD 活化能和不同位置 H- 的轨迹描述；`EC-E009` 报告 DFT-NEB 的势垒。两者属于计算材料；能否支持具体 knock-off 机制须针对其路径和观测量评估，不能仅凭势垒接近就判定机制得到确认。

**当前产物需要人工核对：**`EC-E010` 把 knock-off 解释作为结果登记，`EC-M006` 再把它用于同一机制解释；`EC-P004` 还声称该解释由 `EC-E007` 汇总得到。根据已核对的 B0037，这些关系存在将解释当作自身证据、或把作者推断写成明确派生的风险；本示例保留关系供核对，不伪装已修复。`RC-Q004` 已提示机制需要验证，但它没有明确审查 `EC-M006` 的循环性。

**其他来源状态：**`TC-N006` 中 1H NMR 方法一项被模型判为“部分支持”，原因是现有引用块未直接写出该方法。应继续核对对应原始文献或其他已取得资料；未取得前保留这一限制。

## 9. 验收标准

### 9.1 结构和阅读行为

- 从 `note.md` 和静态 `note.html` 可直接读到核心命题及其条件，并在同一论点单元找到已登记的证据、作者用途、桥、定点审查和适用的综合评议；没有的项显示其真实状态。
- 直接关联、沿路径间接关联、候选和未关联区分明确；证据目标为节点、边或 `bridge` 时分别展示，绝不由图遍历升级成直接支持。
- 指向证据的审查注明目标是证据；指向边或 bridge 的审查注明实际范围；不存在 `RC-A` 时不根据 `RC-Q` 自动生成总体可靠性。
- 同一 `EC-E` 在多处被引用时 ID 不变；`EC-G` / `EC-U` 不被渲染成独立重复实验。多核心、多父节点、空链、缺复核、待决候选及来源冲突均可显示。
- HTML 特殊字符正确转义，文本与 Markdown 的科学内容、来源状态一致；Zotero 视图无需 JavaScript、SVG 或外部文件即可读懂主要论证与限制。长字段不能因固定摘要长度静默丢失关键条件；必要时展示完整字段或明确截断并提供本地追溯。
- SVG 多理由不重叠、文本不越界；审查和候选不是支持路径。自动几何检查结合实际图形人工查看，不能仅凭字符串断言布局可读。
- Markdown 在支持安全内联 HTML 的目标渲染器中呈现蓝色主色调；过滤样式时层级、状态与内容仍可阅读。HTML 和 SVG 采用相同蓝色家族，状态不单靠颜色区分。Zotero 的颜色保留及显示以真实回读和界面检查为准，未验证时标为未知。
- 生成内容符合第 4.5 节的 ASD-STE100 清晰写作要求；人工检查术语一致、主语和条件明确、句子简洁，同时保留原文限定、数值和不确定性。不宣称中文通过英文规范正式认证。

### 9.2 科学内容与来源质量

- 对 `FK5UDDB2` 至少人工抽查上述电导路径、活化能范围、NNP 外推和 knock-off 路径，核对主文和 SI 的来源、对象、单位、条件、来源判断与审查范围。
- 明确保留 1H NMR 引用不足、H2 气氛、模拟与实验差别，以及机制仍需验证的限定；不能把旧 `EC-E010 → EC-M006` 自动视为可靠的独立证据。
- 复核模型不得把作者“提出机制”直接判为“机制已证实”；审查差异与缺失不自动转成论文错误。对有条件、无误差范围、不同样品、不同温区、图内数据及 OCR 损坏分别标示。
- 除真实输入的结构与来源身份约束外，不以结果数值、字面表达、固定记录数或预期科学结论作为运行失败门槛。引用合法、模型来源“支持”、RC 评议和人工复核各自独立呈现。

### 9.3 可复现与副作用

- 同一权威 JSON、复核报告与视图版本产生一致的阅读投影；ID 和来源指针解析到原对象，任意派生输出不改变权威内容。
- 日志和运行清单能区分实际使用的输入、代码、提示词、生成/修复/复核模型及可获得的用量；未知字段显示未知。
- 离线测试不调用真实服务或写 Zotero；本地运行与远程写入结果分别报告。原始论文、旧产物和既有 note 保持不变。
- `--local-only` 不创建 Zotero 附件。正式发布只有 note、SVG 附件和标签均按各自契约回读确认后才标记完成；失败响应清楚区分已完成步骤、附件内容校验状态与需要对账的步骤。
- 模拟明确拒绝、上传响应未知、附件回读失败、多个候选、标签失败和账本失败；恢复时不重复创建已确认的 note 或附件。真实服务上传及 Zotero 预览、颜色测试单独记录授权、目标、实际结果与未覆盖库类型。
